# 知识库

## 定数阶梯策略

> 基于 Rating 公式反推：`avg_single = total/50`，SSS+(22.4) / SSS(21.6) / SS+(21.1)

### 0-10000
- B50 均分 ≤ 200，对应 9-10 级 SSS
- 优先把 11-12 级基础谱面打到 SSS，快速填满 B50
- 不建议过早挑战 13+ 谱面

### 10000-12000
- B50 均分 200-240，对应 12 级 SSS 或 13 级 SS+
- 以 12~12+ SSS 为主，开始尝试 13 级入门曲
- 关注五维短板，针对性选曲

### 12000-13000
- B50 均分 240-260，对应 12+ SSS+ 或 13 SSS
- 逐步推 13 SSS，选择性尝试 13+ 和 14 级入门曲
- 补齐 B35 地板分：优先提升低成就 Old 曲

### 13000-14000
- B50 均分 260-280，对应 13 SSS~14 SS+
- 13~13+ SSS 为核心，尝试 14 级 SS+
- B15 地板分通常比 B35 高，优先推新曲

### 14000-14500
- B50 均分 280-290，对应 13+ SSS~14 SSS
- 以全 14 SS+ 或 13+ SSS 为目标
- 选择性挑战 15 级入门曲，关注 FC/AP 率

### 14500-15000
- B50 均分 290-300，对应 14 SSS
- 14 级高达成率 SSS 为核心，冲击 14+
- 每首曲目的 0.5% 提升都很关键

### 15000-16000
- B50 均分 300-320，对应 14~14+ SSS~
- B15 全部 14.5+ SSS+，B35 地板提升至 14.3+
- 14.5~14.8 水分曲是性价比最高的推分目标

### 16000-16200
- B50 均分 320-324，对应 15 级 SSS 起步
- B15 全部 14.9+ SSS+，B35 地板提升至 14.5+
- 15 级精选谱面冲击 SSS+

### 16200-16400
- B50 均分 324-328，需要 15 SSS+ 支撑
- 核心攻克 15 级高达成率，B50 全 15.0+
- 每 0.5% 精度提升都需大量练习

### 16400+
- B50 均分 ≥ 328，需全 14.5+ SSS+ 或 15 SSS
- AP 额外 +1 分可降低对 SSS+ 的依赖
- 转向成就系统（将牌/极牌/神牌），享受尽头风景

## 成就与牌子

### 将牌
- **俗称**：将
- **达成条件**：当前版本内全部 BASIC~MASTER 难度谱面达成 SSS（100.0%）
- **备注**：通常需要在对应版本更新前完成

### 极牌
- **俗称**：极
- **达成条件**：当前版本内全部 BASIC~MASTER 难度谱面达成 FC（或 FDX）
- **备注**：难度高于将牌

### 神牌
- **俗称**：神
- **达成条件**：当前版本内全部 BASIC~MASTER 难度谱面达成 AP（All Perfect）
- **备注**：要求极高，是全 AP 玩家的终极目标

- **达成条件**：当前版本内全部 BASIC~MASTER 难度谱面达成 FDX（Full DX，含全 AP + 全 Critical Perfect）

## SLIDE 判定机制

> 来源：Inku墨《15分钟彻底搞懂SLIDE！》（BV1Tq4y1f73d, 2021-09）。判定队列模型为社区推定，非官方源码。

### 判定队列模型

每个 Slide 的判定可拆分为不可分割的任务队列：

- **on（状态）**：手指按下并停留在某区域的状态
- **off（事件）**：从按下到松开的动作

规则：
1. **任意时刻队列中前三个任务接受判定**
2. 判定发生后，该任务**及其前面的所有任务**退出队列
3. 队列空 = Slide 判定完毕

### 跳区现象

| 操作 | 结果 | 解释 |
|------|------|------|
| 1A→4A 弧形 slide 点 `1A,3A,4A` 或 `2A,4A` | ✅ 完成 | 跳过 2A 不影响 |
| 按住 1A 再点 3A | ❌ 无反应 | 3A on 不在前三任务（1A off 挡在队列前） |
| 松开 1A 后再点 3A | ✅ 完成 | 1A off 退出后 3A 进入前三 |
| 依次按住 1A,2A,3A,4A 不松 | ✅ 完成 | 每个 on 依次判定 |

**on 是状态而非动作**：slide 出现前糊住全部区域，出现即被判定。
**off 是事件而非状态**：不碰屏幕时 off 不会自动判定。

### 松手判定的真相

"只有松手才判定"是**动画表现**，不是内部判定逻辑。按住 2A 不松手时 1A 区域也会消除（2A on 判定使 1A on/off 一并退出队列）。

### 扇形 Slide 特殊规则

- 旧框体视作 **3 条直线**（A8→A3、A8→A4、A8→A5）
- **A4 可留尾**：A3、A5 划完后 A4 不点也可判定；此时最后一个任务为 **B4 off → 松手判定**（旧框 bug）
- **DX 新框体已修复**：B4 改为按下判定（队列中删除 B4 off）
- D 区引入使 A 区变窄 → 扇形判定宽松化：**A4/A5 可代替 A3** 参与判定（手小划不宽也能判）
- 新老框体感应区有变化（D/E 区），但除扇形外 Slide 基本判定不变

## 谱面术语补充

| 术语 | 准确含义 |
|------|------|
| 跳区 | 利用判定队列规则跳过中间区域完成 Slide（如 1A→4A 只点 1A,3A,4A） |
| 松手判定 | 动画层表现；指最后一个 off 任务（如旧框 B4）尚未完成时需松手触发 |
| 星星旋转 | 设置项；星星头旋转速度代表启动后滑行速度，可区分快慢星 |
| 搓星星/搓搓 | 手指在星星路径上快速来回搓动代替跟随滑动的邪道打法（省体力） |
| 伪双押 | 搓法中将"拐点+单点"按双押节奏处理，避免粉键的关键认知 |
| 防蹭 | 移动手指时避免误触其他判定区的控制技术（如打星星时手移出 A 区） |
| 正攻 | 按谱面默认方式处理，不使用简化打法（费体力但稳定） |

## 发力体系（体力模型参考）

> 来源：Terocrim 发力教学（BV1znFteAEA3, 2025-01）

### 五部位发力

| 部位 | 使用场景 | 疲劳特征 |
|------|------|------|
| 指尖 | 最精细敲击 | 低 |
| 手腕 | 双单双单、对角双押 | 低 |
| 手背 | 抓绝赞/低差分准度（固定手型防拍框） | 中 |
| 小臂 | 位移需求；**仅高速交互等爆发配置绷紧** | 中高 |
| 大臂 | 仅出张和转圈等大幅度配置 | 高 |

### 关键结论
- **越级错发力**：底力不足时本应用手腕却用大臂 → 易拉伤
- 高等级体力不足主因之一是**多余动作太多**
- 减少大臂动作是省力的第一要务

### 推分策略补充
- 全 3S 对底力提升微乎其微 → 推荐单曲 **100.8%+ / AP**，提升更大
- AP 不必初期追求，待 100.8/100.9 稳定后再凹

## 官方音符名称（画面核验）

> 来源：maimai 官方新手教程画面逐帧核验（BV18T411A7FD, 2026-08-05 用 video-analyzer 画面分析）
> ⚠️ 注意：AI 字幕误听严重（"cap/fly/特ch"），**以画面文字为准**

| 官方名称（画面） | 类型 | 判定方式 |
|------|------|------|
| **TAP** ノーツ | Tap | 与判定线重合时拍按键 |
| **HOLD** ノーツ | Hold | 与判定线重合开始，一直按住直到消失 |
| **SLIDE** ノーツ | Slide | 先拍星星头（☆）→ 等一拍 → 跟随轨迹滑动 |
| **TOUCH** ノーツ | Touch | 快门闭合瞬间触摸屏幕 |
| **Touch Hold** | 触摸长按 | 在音符消失前一直按住不放 |
| Break | Break（绝赞） | 与 Tap 同操作（此视频未展示，官方称绝赞） |

**字幕误听对照**：cap→TAP / fly→SLIDE / 特ch→TOUCH / 好的音五→BREAK / touch好的→Touch Hold

## simai-sharp 解析器行为

| 行为 | 说明 |
|------|------|
| **星星 = Tap + isStar** | 所有 Slide/星星音符在 simai-sharp 中表示为 `NoteType.Tap (0)` + `isStar=true`，而非 `NoteType.Slide (3)`。Slide 路径信息通过 `slidePaths` 属性访问 |
| **不支持 `[#秒数]`** | 部分谱面（如系ぎて）使用 `[#7.014]` 直接指定 Slide 时长秒数，simai-sharp 会抛出解析错误 |
| **不支持浮点 BPM** | `(88.8)` 形式的 BPM 标记可能导致解析异常 |
| **timingChanges 始终可用** | 变速信息通过 `chart.timingChanges` 正确返回 |
