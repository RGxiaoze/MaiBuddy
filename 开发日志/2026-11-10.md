## 三、localhost / 127.0.0.1 origin 隔离坑（本轮主要教训）

`redirect_uri` 硬编码为 `http://127.0.0.1:5173/`，所以无论从哪里发起授权，
落雪都会把用户送回 `127.0.0.1`。而 sessionStorage 按 origin 隔离，
在 `localhost` 写入的 PKCE verifier 到 `127.0.0.1` 读不到。

**症状**：走完整个授权流程、回跳后才报「找不到本次授权的来源，请重新发起登录」。
错误发生在链路末端，前面每一步看起来都正常，用户很难自行定位。

**定位方法**：用假 code 模拟完整往返（127.0.0.1 写入 → 跳落雪 → 回跳 `?code=FAKE&state=…`
→ Vite 302 到 `/MaiBuddy/`），弹窗显示 `invalid authorization code` 而非「找不到来源」，
证明 sessionStorage 跨站往返完好、换票请求真实发出，从而排除机制问题、锁定 origin 不一致。

**根治**：dev 下 `redirect_uri` 改为跟随 `window.location.origin`，localhost 与
127.0.0.1 各自回跳到自己的 origin，两边都能用。前提是落雪面板同时登记
`http://127.0.0.1:5173/` 与 `http://localhost:5173/`。

## 五、拒绝授权时的静默失败

用户在授权页点「拒绝」时，回调形如 `?error=access_denied&state=…`，没有 `code`。
`readCallbackParams` 只认 `code`+`state`，于是直接返回 `null`，表现为
「点完拒绝、页面毫无反应」。

补 `readCallbackError`（`oauthCore`）并在回调处理里优先判断：`access_denied` 映射为
「你在授权页拒绝了授权申请，未获得任何数据」，其余错误回落 `error_description`
或原始 `error`。已用 `?error=access_denied` 实测弹窗正常，URL 也被清理。

## 六、畸形链接导致的整页白屏

访问 `https://rgxiaoze.github.io/MaiBuddy/songs&import=1`（漏写 `?`）会整页白屏。

链路：GitHub Pages 404 → `404.html` 把路径编码进 `?/songs~and~import=1` 重定向回根
→ `index.html` 还原为 `/MaiBuddy/songs&import=1` → `<Routes>` 无匹配项渲染 `null`，
连 `MainLayout` 都不出现（所有路由都挂在它下面），于是全白。

内部链接本身没错，`?import=1` 全部正确生成；缺的是兜底路由。
补 `<Route path="*" element={<Navigate to="/songs" replace />} />`，
未知路径统一重定向到曲库页。已实测 `/MaiBuddy/songs&import=1` 正常跳转。
